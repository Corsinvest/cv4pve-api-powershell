## Why

The Proxmox VE web interface is made for one action at a time. Snapshot forty VMs before an update,
list every VM with its disks for an audit, clone a template ten times, shut down a lab every evening:
by hand it is slow and error-prone, and the shell of a node is not where you want to run your company's
scripts.

VMware administrators have PowerCLI for this. cv4pve-api-powershell is the same idea for Proxmox VE:
the whole API as PowerShell cmdlets, so the scripts, scheduled tasks and habits you already have keep
working — objects in the pipeline, `Where-Object`, `Export-Csv`, `Get-Help`.

## On your machine, API only

The module runs where PowerShell 7 runs — Windows, Linux, macOS, a management VM, a CI runner — and
talks only to the Proxmox VE REST API on port 8006. Nothing is installed on the nodes and no SSH is
needed. What a script can do is what its API token or user is allowed to do: give it a token with just
the privileges it needs, see [Permissions](/cv4pve-api-powershell/permissions/).

## Where it fits

The cv4pve suite follows the Unix philosophy: each tool does one thing and does it well.
cv4pve-api-powershell is the one for your own PowerShell scripts: any API call, with objects. Prefer a
command line that works in any shell? [cv4pve-cli](https://corsinvest.github.io/cv4pve-cli/) calls the
same API with text output. For an inventory or a health check of the cluster, ready to run, see
[cv4pve-report](https://corsinvest.github.io/cv4pve-report/) and
[cv4pve-diag](https://corsinvest.github.io/cv4pve-diag/).
